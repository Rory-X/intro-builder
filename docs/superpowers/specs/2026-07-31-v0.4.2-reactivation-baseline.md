# v0.4.2 Reactivation Baseline Design

**Date:** 2026-07-31
**Status:** Implemented (awaiting review and release)
**Depends on:** `docs/superpowers/specs/2026-06-25-agent-stability-ux-design.md`

## 1. Why This Slice Exists

The repository has not shipped since 2026-06-25. `main` is healthy at its last
known CI run, but the next Agent stability PR is conflicted, PartyKit currently
trusts unsigned JWT payloads, dependency/security automation is absent, and the
project status index still describes version 0.3.2 while the packages are at
0.4.1. New product work should not start on top of those unknowns.

This slice restores a trustworthy release baseline before onboarding, job-match,
or monetization work begins.

## 2. Goals

1. Reapply only the unmerged Agent stability commit from PR #105 onto current
   `main`, without replaying the already-merged resume version commit.
2. Make PartyKit collaboration connections fail closed unless their JWT is
   valid, unexpired, signed with the configured secret, and bound to the room.
3. Make the PartyKit deployment fail before deploy when `COLLAB_JWT_SECRET` is
   not configured.
4. Add scheduled dependency-update PRs and CodeQL analysis without enabling
   automatic merges or changing runtime dependency versions.
5. Restore documentation truth: current version, shipped capabilities, active
   plans, remote names, and the actual available project skills.
6. Re-establish a green local verification baseline and bump the application to
   0.4.2.

## 3. Non-Goals

- No dependency major upgrades. The 14 detected major upgrades need separate,
  stack-specific plans.
- No onboarding, overflow indicator, ATS report, payment, or other new product
  behavior.
- No redesign of collaboration session storage or PartyKit/Yjs persistence.
- No automatic dependency merge or production deployment from this branch.
- No resurrection of stale remote branches whose behavior already landed by a
  different implementation.

## 4. Key Decisions

### 4.1 Salvage PR #105 by commit, not by conflict resolution

PR #105 contains the already-merged resume version work plus commit
`fc9d1444e` for Agent stability. Only the latter is replayed. This keeps the
diff reviewable and avoids resolving duplicate migration and version-history
changes.

### 4.2 Collaboration authentication is fail closed

PartyKit rejects connections when the token is missing, malformed, expired,
signed with another secret, has an invalid payload, or names a different
`resumeId`/`sessionId` than the requested room. There is no guest fallback for a
protected collaboration room.

The existing HS256 token format remains unchanged. This is a boundary repair,
not a protocol migration.

### 4.3 Security automation reports; humans still decide

Dependabot opens grouped patch/minor PRs and individual major-version PRs.
CodeQL analyzes JavaScript/TypeScript on pushes, pull requests, and a schedule.
Neither workflow merges, deploys, or modifies application data.

### 4.4 Dependency refresh is a follow-up release

The reactivation release records the outdated inventory but does not combine
AI SDK, TipTap, Zod, TypeScript, drag-and-drop, or Puppeteer upgrades. Each
protocol-heavy group must preserve its own test and rollback boundary.

## 5. Risks and Mitigations

- **PartyKit production secret is missing:** deployment now stops before
  publishing an unusable worker; the same secret must be configured in the Web
  and PartyKit environments.
- **Old clients carry an expired token:** the socket fails and the existing Web
  flow requests a fresh owner token or mentor join token.
- **PR #105 assumptions drifted:** its existing focused tests and the full repo
  gates must pass against current `main`; conflicts are resolved in favor of
  current version-history behavior.
- **Dependency PR noise:** patch/minor updates are grouped and open PR count is
  capped. Major upgrades remain explicit.

## 6. Acceptance Criteria

- Invalid PartyKit connections are rejected before Yjs sync begins.
- Valid owner and mentor tokens are accepted only for their own room.
- PartyKit deploy checks `COLLAB_JWT_SECRET` alongside deploy credentials.
- The Agent stability tests and all repository gates pass.
- Dependabot and CodeQL configuration is valid and contains no auto-merge path.
- Project status documents identify 0.4.2 and the next product slice accurately.
