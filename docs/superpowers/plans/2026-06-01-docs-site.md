# 文档站 (Docs Site) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate a fumadocs-powered documentation + blog site into the existing intro-builder Next.js 16 project, serving job-hunting guides, resume packaging tips, and learning roadmaps for Chinese college students.

**Architecture:** fumadocs-mdx compiles `.mdx` content at build time via a Vite-based pipeline; `fumadocs-core` provides the content source/loader; `fumadocs-ui` renders the docs layout (sidebar, TOC, search). Content lives in `content/docs/` and `content/blog/`. Routes live at `app/docs/[[...slug]]/` and `app/blog/`. The existing shadcn design system is preserved via `fumadocs-ui/css/shadcn.css`.

**Tech Stack:** fumadocs-core v16, fumadocs-ui v16, fumadocs-mdx v15, Next.js 16, Tailwind v4, React 19

**Spec:** `docs/superpowers/specs/2026-06-01-docs-site-design.md`

```ts
import { defineDocs, defineCollections, defineConfig, frontmatterSchema } from "fumadocs-mdx/config";
import { z } from "zod";

export const docs = defineDocs({
  dir: "content/docs",
});

export const blog = defineCollections({
  type: "doc",
  dir: "content/blog",
  schema: frontmatterSchema.extend({
    author: z.string().default("intro-builder"),
    date: z.string().or(z.date()).transform((value, context) => {
      try {
        return new Date(value);
      } catch {
        context.addIssue({
          code: z.ZodIssueCode.custom,
          message: "Invalid date",
        });
        return z.NEVER;
      }
    }),
    tags: z.array(z.string()).optional(),
    draft: z.boolean().optional().default(false),
  }),
});

export default defineConfig();
```

```tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { DocsPage, DocsBody } from "fumadocs-ui/page";
import { docsSource } from "@/lib/source";

interface PageProps {
  params: Promise<{ slug?: string[] }>;
}

export default async function Page({ params }: PageProps) {
  const { slug } = await params;
  const page = docsSource.getPage(slug);

  if (!page) notFound();

  const { body: Mdx } = await page.data.load();

  return (
    <DocsPage toc={page.data.toc}>
      <DocsBody>
        <h1 className="text-3xl font-bold">{page.data.title}</h1>
        {page.data.description && (
          <p className="text-lg text-fd-muted-foreground mt-2 mb-6">
            {page.data.description}
          </p>
        )}
        <Mdx />
      </DocsBody>
    </DocsPage>
  );
}

export function generateStaticParams() {
  return docsSource.generateParams();
}

export async function generateMetadata({ params }: PageProps): Promise<Metadata> {
  const { slug } = await params;
  const page = docsSource.getPage(slug);

  if (!page) return {};

  return {
    title: page.data.title,
    description: page.data.description,
  };
}
```

```mdx
## 什么是暑期实习？

暑期实习（Summer Intern）是大厂每年 3-5 月集中招聘、7-9 月入职的实习项目。它有几个显著特点：

- **竞争激烈**：头部公司 HC 有限，面试难度接近正式校招
- **转正率高**：通常 60-80%，是拿到校招 offer 的捷径
- **时间固定**：一般要求 2-3 个月全职实习

## 什么是日常实习？

日常实习是企业全年滚动招聘的实习岗位，特点：

- **门槛相对低**：没有集中招聘季的竞争压力
- **时间灵活**：可以兼顾课程，一周 3-4 天
- **转正不确定**：取决于部门 HC 和你的表现

## 怎么选？

| 维度 | 暑期实习 | 日常实习 |
|---|---|---|
| 最佳时机 | 大三下学期（3-5月投递） | 大二/大三随时 |
| 竞争程度 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| 转正率 | 60-80% | 20-40% |
| 积累经验 | 深度项目经历 | 广度体验 |
| 建议 | 目标明确的同学首选 | 探索方向、积累第一份实习 |

## 行动建议

1. **大二**：先找一份日常实习，积累经验和简历素材
2. **大三上**：准备暑期实习的投递，刷题 + 完善简历
3. **大三下 3-5 月**：全力冲暑期实习
4. **暑期实习结束**：如未转正，秋招是最后一次大规模机会
```

```mdx
## 什么是 STAR 法则？

STAR 是描述项目经历的经典框架：

- **S**ituation（情境）：项目背景是什么？
- **T**ask（任务）：你负责什么？
- **A**ction（行动）：你具体做了什么？
- **R**esult（结果）：产出了什么可量化的成果？

## 反面例子

> 负责公司官网的前端开发，使用 React 技术栈，完成了多个页面的开发。

问题：没有情境、没有具体行动、没有量化结果。

## 正面例子

> 针对官网首屏加载耗时 4.2s 导致跳出率偏高的问题（S），主导前端性能优化专项（T）。引入路由懒加载 + 图片 WebP 格式转换 + 关键 CSS 内联（A），首屏 LCP 从 4.2s 降至 1.8s，跳出率降低 23%（R）。

## 练习方法

1. 列出你做过的每个项目/任务
2. 对每个项目，问自己：「为什么要做？做了什么？结果如何？」
3. 用数字量化结果（性能提升 X%、用户增长 X 人、节省 X 小时）
4. 没有精确数据？用合理估算（「约」「超过」「近」）

## 在 intro-builder 中使用

使用 [intro-builder](/) 编辑简历时，在「项目经历」板块的描述中套用 STAR 框架，让每段经历都有说服力。
```

```mdx
## 2026 暑期实习时间线

各大厂暑期实习的投递节奏大致如下：

| 时间 | 事件 |
|---|---|
| 1-2 月 | 提前批（内推为主） |
| 3-4 月 | 正式批开放 |
| 4-5 月 | 笔试面试密集期 |
| 6 月 | 发 offer、补录 |
| 7-9 月 | 实习期 |

## 现在该做什么？

如果你正在阅读这篇文章，说明暑期实习季已经开始。以下是按优先级排列的行动项：

1. **完善简历**：用 [intro-builder](/) 制作一份结构清晰的 PDF 简历
2. **投递**：不要等到「准备好了」再投——投递本身就是练习
3. **刷题**：每天 1-2 题 LeetCode，重点刷高频题
4. **复习八股**：浏览器原理、网络、框架原理
5. **准备项目话术**：用 [STAR 法则](/docs/resume-guide/star-method) 准备每个项目的 2 分钟介绍

## 心态建议

- 被拒是常态，不要因为几次失败就放弃
- 大厂不是唯一选择，优秀的中小厂同样能给你成长
- 实习不是终点，是积累经验的起点

祝你投递顺利！
```
