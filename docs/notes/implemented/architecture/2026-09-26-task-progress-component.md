# Agent Note: 任务卡组件只渲染投影，不自己判断「已保存」

Status: implemented

## Problem

P06 任务 2/7 要求把任务卡投影接到 UI，plan 的文件范围明确列出
`components/agent/task-progress.tsx`。

但接线有一处**很容易做错的地方**：组件完全有条件自己判断状态 ——
它拿到 `card.status`，写 `status === "done" ? "已保存" : ...` 是最自然的写法。

那样做的后果是**投影层的约束在 UI 层失效**：

- 投影层特意把 `status`（终态事件决定）与 `hasPersistedChanges`
  （唯一依据是 `mutation.committed` 回执）分成两个字段，因为模型可以
  说完话而什么都没写；
- 一旦组件用 `status` 推断「已保存」，用户就会在诊断类任务后看到「已保存」，
  而实际什么都没写。

另外 plan 有两句具体要求落在组件层而非投影层：

- 「**长任务可以折叠，用户滚走时不强制拉回底部**」；
- 「没有事件不虚构进度」——投影层返回 `null` 标题时，组件不能显示一个空卡片。

## Decision

### 1. 组件不重新判断任何状态

「已保存」标记只读 `card.hasPersistedChanges`；标题只调 `taskCardHeadline(card)`。

组件内**没有**对 `card.status` 的字符串比较来判断是否保存 ——
测试专门覆盖「`status === "done"` 且无回执 → 不显示已保存」这一条。

### 2. 无可展示内容时返回 `null`

投影在「running 但无步骤」时返回 `null` 标题。组件据此**不渲染任何东西**：
显示一个空卡片比不显示更糟（用户会以为有内容正在加载）。

### 3. 折叠状态不被步骤数变化重置

`collapsed` 只由用户点击改变，**不**随 `card.steps.length` 变化。
若随着重置，用户折叠后一旦有新步骤就会重新展开 —— 那正是 plan 要防的
「强制拉回底部」的一种形式。

测试用 `rerender` 模拟「折叠后新步骤到达」，断言折叠状态保持。

### 4. 两个事实一起展示

中断但已保存时，同时显示「连接中断，未完成」与「✓ 已保存」。
落盘是已发生的事实，不因断线而撤销 —— 用户需要同时知道这两件事。

## Alternatives considered

- **组件里用 `status` 推断「已保存」** — 少读一个字段，代码更短。
  否决原因：那正是本任务要防的错误。投影层把两个字段分开是有意的，
  组件用其中一个推断另一个等于把那个设计抹掉，而且测试很难发现
  （除非专门写一条「done 但无回执」的用例 —— 我确实写了）。
- **把折叠状态放进投影层**（`TaskCard.collapsed`）— 状态集中，便于持久化。
  否决原因：折叠是**纯展示偏好**，与事件流无关。放进投影会让纯函数依赖 UI 状态，
  也会让「重放同一批事件」的测试需要额外构造折叠参数。
  将来若要持久化折叠偏好，应当走 localStorage 而不是事件投影。
- **无可展示内容时渲染一个骨架屏** — 用户能看到「有东西在加载」。
  否决原因：投影层明确返回 `null` 就是「现在没有可说的」，骨架屏是在暗示
  有内容即将到来 —— 那是虚构进度的另一种形式。
- **把失败步骤的原始错误码也渲染出来**（便于用户反馈问题）—
  否决原因：用户拿 `target_not_found` 做不了任何事。投影层已把它翻成
  「找不到这条内容，可能已被删除」，组件渲染那个即可。测试断言渲染结果
  不含原始码。
- **组件自己订阅事件流**（而不是接收投影好的 `card`）— 更「自治」。
  否决原因：那会把事件订阅与展示耦合在一起，且让组件无法用纯 props 测试。
  当前设计（父组件投影、组件只渲染）让 RTL 测试可以穷举各种卡片状态。

## Consequences

- **收益**：投影层的两条核心约束（不虚构进度、完成≠保存）在 UI 层仍然成立；
  折叠行为符合 plan 的「不强制拉回」。
- **代价**：多一个组件与一份 RTL 测试；父组件需要负责投影（调用
  `projectTaskCard`）并把 `card` 传进来。
- **已知上限**：
  - **尚未接入 `floating-agent-chat.tsx`**。组件本身可用，但还没有真实调用方 ——
    因此「在实际会话中显示任务卡」这件事**尚未完成**。接线需要改那个大组件
    （它同时承载停靠、移动端、审批等逻辑），属后续工作。
  - **折叠偏好不持久化**。刷新后回到默认展开。
  - **plan 要求的 `resume-change-set-card.tsx` 尚未创建**。提案卡投影
    （`lib/ai-client/change-set-card.ts`，32 例）已就绪但同样没有组件。
  - 未做键盘导航的完整验证（折叠按钮可聚焦、可回车触发，但未测 Tab 顺序）。
- **什么信号发生时该重访**：若用户反馈「诊断之后显示已保存」，
  检查是否有调用方在某处用 `status` 覆盖了 `hasPersistedChanges`。
  若要支持「点击步骤跳到对应内容」，需要给 `TaskStep` 加 section/itemId 字段
  （当前只有 `id` 与 `label`）。

## Verification

- `apps/web/tests/unit/ai-task-progress.test.tsx`（16 例，plan 点名的文件名）：
  - **不虚构进度**：无标题且无步骤时不渲染、待机但有步骤时渲染、
    运行中但无步骤时不渲染；
  - **完成与保存分开**：**done 但无回执 → 不显示「已保存」**、
    有回执 → 同时显示「已完成并保存」与「✓ 已保存」、
    **中断但已保存 → 两个事实一起展示**；
  - **等待用户**：显示标题与问题文本；
  - **失败步骤**：显示可操作 detail 且不含原始错误码；
  - **冲突**：有冲突显示数量、无冲突不显示「0」；
  - **折叠**：默认展开、可折叠再展开、**步骤增加不重置折叠状态**、
    支持默认折叠、无步骤时不显示折叠按钮；
  - **不泄漏**：渲染结果不含工具名、payload、密钥前缀。
- 全量：`pnpm test` 1488 例通过、`typecheck` 四包全绿、`lint` 0 error（12 warning = 基线）。
