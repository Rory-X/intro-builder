# Agent Note: 无消费方的旧路由转为 410，而不是删除或重定向

Status: implemented

## Problem

P07 任务 3 要求「旧公开 API 可短期返回明确 410/客户端升级提示，
**不能重定向到旧服务**」。

上一个提交（退役审计棘轮）暴露了现状：4 个可达旧服务调用点 + 3 个待归档模块。
但「一次全切」做不到 —— 因为其中一条有**活路径**：

```
默认 surface = "panel" → AgentPanel → AgentAgUiRuntimeProvider → /api/agent/direct-runs
```

而 `direct-runs` 需要组件切换（改 2511 行的 `floating-agent-chat.tsx` +
翻转默认 surface）才能退役。那是 P07 任务 3 的主体工作。

那么这一轮做什么？核实发现另外两条路由**零消费方**：

- `/api/agent/session`：签发 Agent JWT 转发 `/v1/session`。组件、hooks、lib
  都没有引用它，只有自己的测试在调 —— 一条「为了演练而存在」的路径。
- `/api/agent/messages`：签发 token 转发 AG-UI 消息。浮窗走
  `/api/agent/floating/chat`，面板走 `direct-runs`，它是第三条。

## Decision

把这两条转为 **410 stub**，并抽出共享的响应模块。

### 1. 为什么是 410 而不是 404 或 503

- **404** 无法区分「路径写错了」与「功能已下线」。调用方会去查拼写，
  而真实原因是版本过期。
- **503** 暗示「暂时不可用，稍后重试」—— 但这条路径**不会再回来**。
  让客户端重试一个已退役的入口是纯粹的浪费。
- **410 Gone** 的语义正是「这里曾经有东西，现在永久没有了」。

### 2. 为什么不直接删除路由文件

410 是**可观察的退役信号**：运维能据此确认「确实没有流量」，
而这正是 P08「旧微服务暂保留但无请求」的判据之一。
直接删掉会让这个信号消失（404 无法区分「没人调」与「路径错了」）。

### 3. 为什么不重定向到旧服务

plan 明确禁止，理由是实质性的：重定向会让「旧服务无请求」这个退役信号
一直达不到 —— 而那是 P08 决定能否下线服务器的依据。

若客户端版本过旧确实需要旧服务，**正确做法是它自己升级**，
而不是由服务端悄悄替它续命。

### 4. 响应体给机器可读码 + 替代入口 + 下一步

```json
{
  "error": "这个接口已经下线，请升级到新的 AI 助手入口",
  "code": "route_retired",
  "retiredRoute": "/api/agent/session",
  "replacement": "Web 侧的模型配置与会话管理（/api/agent/floating/sessions）",
  "action": "刷新页面以使用新的 AI 助手；若仍看到此提示，请重新登录。"
}
```

- `code` 是**机器可读**的，客户端据此分支而不是匹配中文文案；
- `replacement` 明确替代入口，不让调用方自己猜；
- `action` 给出下一步，而不是只说「下线了」。

`Cache-Control: no-store` 是必要的：退役信号必须每次都真实到达客户端，
否则用户在缓存过期前会一直看到旧行为。

### 5. 审计棘轮同步更新（这正是它的用途）

调用点从 6 降到 2，余额断言随之从 `6` 改为 `2`。

退役路由**单独一张清单**（`RETIRED_AGENT_ROUTES`）—— 它们与「仍欠债的
调用点」是不同状态：前者的旧服务调用已消除，但 stub 还在（为了信号）。

另外加了一条防误退役断言：有活路径的 `direct-runs` **不在**退役清单里。

## 实测修正的三个问题（红 → 绿）

**一、块注释里写了星号加斜杠的组合，提前终止了注释。**

我在文档注释里写「明确 410」时用了 markdown 加粗语法，其中的
字符序列恰好构成**注释结束符**。后果是后面的中文变成裸代码，
报 `Invalid Character` 与 `Unterminated template literal`（3 处语法错误）。

**更值得记的是**：我修正时写的那行说明**又踩了同一个坑**（自指陷阱）——
修「不要写 X」的注释里写了 X。最后改成描述性文字（「星号加紧跟斜杠的组合」）
才绕开。

**二、测试漏 `await`。** `GET()` / `POST()` 是 async 函数，
我写成 `GET().json()` → `TypeError: GET(...).json is not a function`。

**三、既有测试断言的是已退役行为。** 重写为断言 410 契约
（含源码层「无旧服务调用」的核实）。

## Alternatives considered

- **这一轮什么都不做，等组件切换一起做** — 避免中间状态。
  否决原因：那两条路由是**零消费方**的，它们的退役与组件切换完全独立。
  先做它们能立刻把余额从 6 降到 2，且风险为零（没有调用方会受影响）。
  把可做的事攒着等一件难事，是让「欠债余额」长期不动的常见原因。
- **直接删除两条路由文件** — 最彻底。否决原因：410 是可观察信号，
  而 P08 需要「旧服务无请求」的证据。删除会让「没人调」与「路径错」
  无法区分。plan 也明确说「可短期返回明确 410」。
- **返回 404** — 更符合「路径不存在」。否决原因：见上，
  语义无法区分版本过期与拼写错误。
- **返回 503 让客户端重试** — 更「宽容」。否决原因：这条路径不会再回来，
  让客户端重试是浪费；且 503 会被监控当作「服务暂时故障」，
  掩盖「已按计划退役」这个事实。
- **重定向到 `/api/ai/runs`** — 调用方无感，体验最好。
  否决原因：两条路由的请求体形状与 `/api/ai/runs` **完全不同**
  （旧的带 `messages` 数组或空 body，新的需要 `requestId`/`revision`/
  `modelConfig`）。重定向会让调用方拿到 400 而不是明确的退役提示 ——
  比 410 更难排查。且 plan 明确禁止任何形式的重定向。
- **把两条路由的测试直接删掉** — 退役了就不需要测试。
  否决原因：测试现在断言的是**退役契约**（410、机器可读码、不可缓存、
  源码无旧调用）。这些断言防止有人「顺手把旧实现加回来」——
  而那正是退役最容易反复的地方。

## Consequences

- **收益**：余额从 6 降到 2；两条不受保护的消息转发路径消失；
  退役契约有测试守护；审计棘轮验证了它的设计用途（更新清单即记录还款）。
- **代价**：两条路由从「可用」变成「410」—— 但它们的可用状态本来就没有
  调用方，因此实际影响为零。
- **已知上限**：
  - **`direct-runs` 与 AG-UI runtime 仍活跃**（默认 panel surface）。
    这是剩下的主体工作：需要改 `floating-agent-chat.tsx`、翻转默认 surface，
    且需要人工冒烟。
  - **`/api/agent/sessions` 保留**：它是 Web 自足的（用 `session-store`
    读库，不调旧服务），不是退役对象。审计里列在「能力矩阵：已 Web 自足」。
  - **未加监控/告警**：410 是可观察信号，但目前只靠日志。
    若要让 P08 的「旧服务无请求」有据可依，应当对这两个路由的命中加计数。
- **什么信号发生时该重访**：若收到 410 的真实调用（日志里出现），
  说明有未升级的客户端 —— 那时需要评估是否提供过渡期通知，
  而不是把旧实现加回来。
