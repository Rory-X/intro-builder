# Agent Note: 对话历史「验完就扔」—— 多轮会话会失忆

Status: implemented

## Problem

P07 任务 3 要把浮窗从旧的 `/api/agent/floating/chat`（微服务入口）切到
`/api/ai/runs`。切流前核实新路由的能力，发现一处**会直接毁掉多轮对话**的缺口。

`parseBody` 里写了这段：

```ts
const sizeCheck = validateAiRequestInput({
  message,
  historyLength: Array.isArray(record.history) ? record.history.length : 0,
});
```

它**校验了 `history` 的长度**。但 `StartBody` 类型里**没有 `history` 字段**，
返回值也没带上它 —— 校验完就丢了。然后路由的结尾是：

```ts
history: [],
```

硬编码为空数组。

也就是说：客户端带多少历史都会被丢弃，每一轮都变成「失忆」的第一轮。
用户说「再短一点」，模型不知道在说什么。

**这个缺口在还没有客户端消费方时完全不会暴露** —— 路由测试全绿
（它们只断言事件流行为），`typecheck` 也过。它是 P07 切流的必然爆点。

## Decision

### 1. 抽出 `lib/ai/run-history.ts`，两条路由共用

`continue` 路由内部其实已经实现了历史重建（`buildHistoryFromEvents`），
但它是**路由文件的私有函数**：

- 没有独立测试覆盖；
- `start` 路由无法复用，只能各写一份或干脆留空（当前就是留空）。

两处各写一份必然漂移，而漂移的表现是「继续对话记得上下文、新开一轮不记得」
这种极难察觉的差异。因此抽出来共享，并补 19 例测试。

模块含三个函数：

- `buildHistoryFromEvents`：单 Run 的事件 → 对话消息；
- `buildSessionHistory`：多轮（多 Run）→ 完整对话；
- `trimHistory`：裁到最近 N 条。

**刻意做得很薄**：只取用户可见的问答对（`text.delta` 累积 + 提问）。
**不重放工具调用** —— 已提交的操作应按回执查询，重放会让「继续」变成第二次修改。

### 2. 让 `history` 真正透传，并做严格形状校验

`StartBody` 加 `history: HistoryMessage[]`；`parseBody` **逐条**校验
`role`（只允许 `user` / `assistant`）与 `content`（必须是字符串）。

**非法条目拒绝整个请求，而不是静默丢弃**：静默丢弃会让模型拿到一段
缺了中间环节的对话 —— 那比没有历史更糟（模型会基于错误的上下文推理）。

校验放在**长度校验之前**：先收敛成合法形状再数长度，
否则「200 条非法条目」会先被长度检查以错误的理由拒绝（报「太长了」而
真实原因是内容非法）。

## 实测修正的三个问题（红 → 绿）

**一、`trimHistory` 未超限时返回空数组。**

第一版把「未超限」与「超限」写成两个分支，而未超限那个分支我漏了
`return history`（只剩一句长度判断），于是未超限时返回 `[]`。
测试抓到：`expected [] to deeply equal [ Array(2) ]`。

改为**统一取尾部再清理**：既不重复逻辑，也顺带处理了「未超限但以助手消息
开头」这种同样非法的形状（`buildSessionHistory` 在某轮没有用户消息时会产生它）。

**二、测试漏 mock 导致假失败。** 路由测试初次跑出 4 个失败，探查后发现是
我的 mock 不完整：`createProviderStreamer` 缺 `ok: true`（路由检查它，
缺了走 400），且漏了 `loadResumeSourceForRun`（得到 undefined → 404）。
**这不是实现缺陷，是我的测试写错** —— 用 probe 打印真实响应体才定位到，
没有靠猜。

**三、lint error：`let history` 应为 `const`。** 我用的是 `push` 而非重新赋值。

## Alternatives considered

- **服务端从已落库事件重建历史**（不信任客户端传来的 history）—
  更防篡改。否决原因：`start` 是「新开一轮」，此时本轮还没有事件；
  之前的轮次虽然落库了，但按会话聚合它们需要**额外的跨 Run 查询**，
  而客户端的会话视图才是用户实际看到的那个（包含本地未提交的中间状态）。
  多轮上下文的权威来源是客户端会话。`continue` 路由仍从事件重建 ——
  因为它在**同一个 Run 内**继续，那里的权威来源确实是落库事件。
- **`history` 非法时静默丢弃非法条目**（保留合法部分）— 更宽容。
  否决原因：会让模型拿到缺了中间环节的对话。用户看到的是「AI 好像忘了
  我之前说的」，而真实原因被静默吞掉，无法排查。
- **只校验长度，校验完仍不带（保持现状）** — 改动最小。
  否决原因：那正是本笔记开头的缺陷。切流后必然爆。
- **在路由里内联这段历史处理**（不抽模块）— 少一个文件。
  否决原因：`continue` 路由已经内联了一份。再内联一份就是两处漂移的开始，
  而这份逻辑包含「不重放工具调用」这类容易做错的判断。
- **`trimHistory` 只在超限时裁剪，未超限直接返回**（我第一版的写法）—
  逻辑更直白。否决原因：漏了 `return`（已由测试抓到），
  且未覆盖「未超限但以助手开头」的非法形状。统一取尾部再清理更简单也更正确。
- **把 `history` 放进 `streamRunAttempt` 的必填参数**（当前已是）—
  否决原因：这是对的做法，保留。它让「忘记传历史」变成编译错误，
  而不是运行时静默失忆。

## Consequences

- **收益**：多轮会话在切流后不会失忆；历史形状有严格校验（不可信输入）；
  `start` 与 `continue` 共用同一份重建逻辑。
- **代价**：多一个共享模块（约 130 行 + 19 例测试）；
  `start` 路由的请求体多一个字段。
- **已知上限**：
  - **`ai_run` 表不存用户消息**。请求体里的 `message` 只在内存中用于本次
    执行，不落库。因此「刷新后重建上一次会话的完整历史」目前**做不到** ——
    需要客户端自己保存会话（浮窗的 `messages` state 就是它的本地副本）。
    若将来要服务端重建，需要新增字段或表。
  - **`trimHistory` 未接入路由**。`start` 路由直接用客户端传来的 history
    （只校验长度不超过 100）。超长时是**整体拒绝**而非自动裁剪 ——
    自动裁剪会让用户看到「AI 只记得最近几轮」而不知道为什么。
    当前选择「明确拒绝」，让客户端自己决定裁多少。
  - 历史上限 100 条是沿用既有常量。长会话可能触及（每轮约 2 条 → 50 轮）。
- **什么信号发生时该重访**：若用户反馈「AI 忘了前面说的」，先查
  客户端是否真的把 history 放进请求体（`run-stream.ts` 的 `streamRun`
  目前**没有**传 history —— 那正是下一步接线要做的）。
  若要支持「刷新后恢复完整历史」，需要让服务端持久化用户消息。

## Verification

- `apps/web/tests/unit/ai-run-history.test.ts`（19 例）：
  - **单轮重建**：delta 累积、结束事件收束、**无结束事件时已累积文本仍有效**、
    空文本不产生消息、**不重放工具调用**、非法 payload 不崩、空数组；
  - **多轮重建**：**按轮次交替用户与助手消息**、**顺序正序**、
    某轮无助手文本仍保留用户消息、空用户消息被跳过、空会话；
  - **裁剪**：未超限原样返回、**超限保留最近的**、
    **裁剪后不以助手消息开头**、maxMessages 为 0 返回空、
    全助手消息被裁到空、**未超限但以助手开头也清理**、
    **默认上限与服务端校验一致**。
- `apps/web/tests/unit/ai-run-route-history.test.ts`（11 例）：
  - **透传**：**合法历史原样传给编排层**、不传时为空数组、
    单轮多条完整保留；
  - **非法拒绝**：history 非数组、**role 非法**、**content 非字符串**、
    条目非对象、白名单而非黑名单、**混入一条非法即整体拒绝**；
  - **长度上限仍生效**：超限 400（`history_too_long`）、恰好 100 条通过。
- 红 → 绿：19 例中 1 例（`trimHistory` 漏 return）、11 例中 4 例
  （mock 不完整导致的假失败，非实现缺陷）一开始失败。修正后全通过。
- 全量：`pnpm test` 1581 例通过、`typecheck` 四包全绿、
  `lint` 0 error（12 warning = 基线）、`build` 通过。
